## 2026-10-27 — Настройка PID и вынос коэффициентов в параметры

### Что сделано
- Коэффициенты PID (`Kp`, `Ki`, `Kd`) и ограничения скорости вынесены в ROS-параметры:
  - Горизонталь: `kp_h`, `ki_h`, `kd_h`, `max_v_h`.
  - Вертикаль: `kp_u`, `ki_u`, `kd_u`, `max_v_u`.
- В класс `PIDController` добавлены сеттеры `set_gains()` и `set_max_output()` для обновления коэффициентов после чтения ROS-параметров.
- В `check_waypoint_arrival()` добавлен сброс интегральной составляющей (`reset()`) при смене целевой точки, чтобы дрон не «тащил» накопленную ошибку с предыдущих участков маршрута.
- Проведена серия полётных экспериментов по подбору коэффициентов.

### Чему научился
- Влияние `Ki` на статическую ошибку и перерегулирование (overshoot):
  - ki=0.001 — сокращает время полёта (с 200 до 140 секунд), дрон летит аккуратно по маршруту (без перерегулирования);
  - ki=0.005 — время полёта 115 сек., но дрон проскакивает целевые точки и возвращается;
 - ki=0.01 — сильные колебания вокруг целевых точек.
- Почему при смене целевой точки необходимо обнулять интегратор (проблема integral windup).
- Влияние шума GPS на дифференциальную составляющую (почему `Kd` без фильтра вызывает вибрации).

### Результат
- Узел можно настраивать без перекомпиляции: `ros2 run drone_controller_cpp pid_machine --ros-args -p ki_h:=0.001 -p kd_h:=0.0`.

## 2026-10-21 — PID-регулятор для удержания позиции

### Что сделано
- Класс `PIDController` с методами `update()` и `reset()`, защитой от derivative kick и ограничением интеграла (anti-windup).
- Переход с публикации позиции (`GlobalPosition` в `/ap/cmd_gps_pose`) на публикацию скорости (`TwistStamped` в `/ap/cmd_vel`).
- Публикация в Earth Frame (ENU) через `frame_id="map"`: X — восток, Y — север, Z — вверх.
- Три независимых PID-контроллера: `pid_north_`, `pid_east_`, `pid_up_` (Kp=0.1/0.1/0.2, Ki=Kd=0, ограничение 5/5/2 м/с).
- Полёт по маршруту из 4 точек с разной высотой через PID: все точки достигнуты, посадка выполнена.

### Чему научился
- Разница между фреймами для позиции и скорости: `FRAME_GLOBAL_REL_ALT` работает для позиции, но не для скорости. Для скорости нужен `frame_id="map"` (ENU).
- Что `type_mask` в `GlobalPosition` не помогает, если тип сообщения не тот — нужен специализированный `TwistStamped`.
- Реализация PID с anti-windup: ограничение `integral_` так, чтобы `Ki*integral <= max_output`.
- Защита от derivative kick: на первом вызове derivative=0, а не `(error-0)/dt`.
- Отличие `frame_id="map"` (ENU) от NED: X и Y меняются местами, Z инвертируется.

### Сложности
- Первая попытка с `GlobalPosition` и `type_mask=3527` не работала — дрон висел на месте, хотя PID выдавал `vN=2.00`. Причина: скорость в GLOBAL-фрейме ArduPilot не принимает.
- Не сразу очевидно, что для ENU надо публиковать `twist.linear.x = v_east` и `twist.linear.y = v_north`, а не наоборот.

### Результат
- Дрон в SITL проходит маршрут по PID: 4 точки с разными высотами, посадка. Время полёта ~3 мин 20 с, расход заряда 56%.
- Код: [pid_twist.cpp](src/drone_controller_cpp/src/pid_twist.cpp), [pid_controller.cpp](src/drone_controller_cpp/src/pid_controller.cpp)

## 2026-09-11 - Добавлена обработка ошибок: батарея, геозона, таймаут связи

### Что сделано
- Подписка на топик "/ap/battery" для отслеживания заряда аккумулятора.
- Проверка удаления от точки взлёта по текущим координатам.

### Чему научился
- Подписываться на дополнительные топики ArduPilot (BatteryState).
- Строить защитную логику по нескольким независимым условиям (заряд, геозона, таймаут связи).

### Результат
- При снижении уровня заряда батареи до 20% переводим дрон в режим возврата на базу (RTL, Mode 6).
- При снижении уровня заряда батареи до 5% - в режим посадки (LAND, Mode 9).
- При удалении от точки взлёта на заданное расстояние переключаемся в режим возвращения (RTL, Mode 6).
- При отсутствии связи более заданного интервала времени (5 сек) логируем это состояние и переходим в режим ожидания. При восстановлении связи продолжаем выполнение полёта по маршруту.

## 2026-08-18 — Первый пакет на C++ (MAVROS)

### Added
**Сборка первого пакета на C++**

Управление дроном через MAVROS на C++ с использованием конечного автомата (State Machine).

---

## Возможности

- **Телеметрия**: подписка на топик `/mavros/state`, вывод состояния в реальном времени.
- **Управление**: последовательное выполнение команд:
  - Переключение в режим `GUIDED`
  - Армирование (`ARM`)
  - Взлёт (`TAKEOFF`)
- **Архитектура**: конечный автомат (`IDLE → WAIT_FOR_CONNECTION → SET_MODE → ARM → TAKEOFF → COMPLETE`).
- **Асинхронность**: все вызовы сервисов MAVROS выполняются асинхронно, без блокировки основного потока.
- **Тестирование**: работает в симуляторе ArduPilot SITL.

---

## Архитектура

### Конечный автомат (`State Machine`)

```text
IDLE → WAIT_FOR_CONNECTION → SET_MODE → ARM → TAKEOFF → COMPLETE
                                ↓        ↓
                                ERROR    ERROR
```
**Каждый шаг:**

- Отправляет асинхронный запрос через MAVROS.
- В колбэке обрабатывает ответ и переключает состояние.
- Таймер (100 мс) управляет переходами, не блокируя поток.

## Компоненты

| Компонент | Назначение |
|-----------|------------|
| Подписка | Обновляет состояние MAVROS (`connected, armed, mode`). Колбэк короткий и неблокирующий. |
| Таймер | Запускает `control_loop()` каждые 100 мс. Управляет миссией по шагам. |
| Клиенты MAVROS | `set_mode`, `arming`, `takeoff` — асинхронные вызовы с колбэками. |

## Стек

- **OS**: `Ubuntu 22.04 LTS`
- **ROS 2**: `Humble Hawksbill`
- **MAVROS**: `ros-humble-mavros`
- **Симулятор**: `ArduPilot SITL`
- **Язык**: `C++17`
- **Сборка**: `CMake + colcon`

### Результат
- Первый работающий узел на C++ с MAVROS, взлёт в SITL.

## 2026-07-31 — Первый пакет на Python (DDS + DroneKit)

### Added
**Сборка первого пакета на Python.** 

Реализован гибридный подход:
- **Телеметрия** получается через DDS-мост (MicroXRCEAgent + топики `/ap/...`).
- **Команды управления** (взлёт, движение) отправляются через DroneKit, подключённый к MAVProxy.

Такой подход позволяет использовать современный DDS для данных и надёжный MAVLink-канал для команд.
## Требования

- Ubuntu 22.04
- ROS2 Humble
- ArduPilot SITL (собран с поддержкой DDS)
- Python 3.10+
- Пакеты: `dronekit`, `pymavlink`, `microxrcedds_agent`

---

 Пример использования

После запуска всех компонентов узел:

    Подписывается на топик /ap/pose/filtered (телеметрия).

    Выводит позицию дрона.

    Автоматически отправляет команду взлёта на 5 метров (через DroneKit).

При успешном запуске вы увидите сообщения о взлёте и рост высоты в телеметрии.

 Примечания

    Параметр DDS_ENABLE в ArduPilot может отсутствовать, это нормально — DDS-модуль активируется флагом --enable-DDS при запуске.

    Для изменения логики управления редактируйте controller_node.py.

    Для работы без DroneKit можно использовать MAVROS (экспериментально).
