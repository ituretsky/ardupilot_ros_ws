## 2026-09-16 — Работа с параметрами

### Что сделано
- Добавлены параметры в командной строке: максимальное удаление от базы и критический заряд батареи.
- Маршрут читается из `share/drone_controller_cpp/missions/route.csv` через `ament_index_cpp::get_package_share_directory`. Путь не зависит от текущей рабочей директории.
- Журнал полёта пишется в `~/drone_logs/track.csv`. Создаётся автоматически при запуске узла.

### Чему научился
- Разделение данных пакета (`share/`, read-only) и выходных данных (`$HOME`, read-write).
- Использование:
  - `ament_index_cpp::get_package_share_directory` для поиска файлов пакета в runtime.
  - `std::filesystem::create_directories` для создания папок.
  - declare_parameter / get_parameter в rclcpp.
- Передача параметров через --ros-args -p name:=value.
- Использование параметров для настройки без перекомпиляции.

### Пример запуска с параметрами
```bash
ros2 run drone_controller_cpp dds_machine --ros-args -p md:=200.0 -p lb:=30.0
```

### Результат
- Узел настраивается без перекомпиляции.
- Пути к маршруту и журналу предсказуемы и задокументированы.
- Код: [controller_node_param.cpp](src/drone_controller_cpp/src/controller_node_param.cpp)

## 2026-09-14 — Логирование телеметрии в CSV

### Что сделано
- Запись телеметрии в `treck.csv` во время полёта: секунда, координаты, высота, заряд, режим, шаг автомата.
- Метод `state_to_string` для вывода имён состояний вместо чисел.
- Метод `mode_to_string` для перевода кодов ArduPilot в названия режимов.
- Подписка на `/ap/status` для получения текущего режима полёта.

### Чему научился
- Формирование CSV через `std::ostringstream` с `std::fixed` и `std::setprecision`.
- Различие между `uint8` в `.msg` и `uint8_t` в C++.
- Открытие/закрытие файлов через `std::ofstream` и RAII-деструктор.
- Использование `static_cast<int>` для enum class при выводе в поток.

### Сложности
- Точность определения положения дрона в симуляторе превышает **0,6м.** Изменение точности сравнения с координатами целевой точки до **1,6** обеспечило стабильное прохождение маршрута даже при временных обрывах связи.
- Режим автоматического возвращения (`RTL`) включает в себя не только возвращение в исходные координаты, но и посадку — добавил ожидание завершения посадки через контроль высоты.
- При `switch(enum class)` компилятор требует явного приведения к `int` в некоторых контекстах.

### Результат
- Лог полёта сохраняется в CSV, пригоден для анализа.
- Код: [controller_node_log.cpp](src/drone_controller_cpp/src/controller_node_log.cpp)

## - 2026-09-11 - Добавлена обработка ошибок: батарея, геозона, таймаут связи

### Что сделано
- Подписка на топик "/ap/battery" для отслеживания заряда аккумулятора.
- Проверка удаления от точки взлёта по текущим координатам.
- Проверка связи узла с FCU ArduPilot через контроль получения телеметрии.

### Чему научился
- Подписываться на дополнительные топики ArduPilot (BatteryState).
- Строить защитную логику по нескольким независимым условиям (заряд, геозона, таймаут связи).

### Результат
- При снижении уровня заряда батареи до 20% переводим дрон в режим возврата на базу (RTL, Mode 6).
- При снижении уровня заряда батареи до 5% - в режим посадки (LAND, Mode 9).
- При удалении от точки взлёта на заданное расстояние переключаемся в режим возвращения (RTL, Mode 6).
- При отсутствии связи более заданного интервала времени (5 сек) логируем это состояние и переходим в режим ожидания. При восстановлении связи продолжаем выполнение полёта по маршруту.

- Код: [controller_node_battery.cpp](src/drone_controller_cpp/src/controller_node_battery.cpp)

## - 2026-09-03 - Переход на DDS + MicroXRCEAgent

### Что сделано
- Реализован контроллер дрона на C++ с конечным автоматом.
- Управление через сервисы ArduPilot (mode_switch, arm_motors, takeoff) и публикацию целевых точек.
- Асинхронная обработка ответов сервисов без блокировки потока.
- Переход от искусственного ожидания выполнения команд (rclpy.spin_once(self, timeout_sec=0.5)) к реальному контролю через функцию check_waypoint_arrival().

### Технологии
- ROS2 Humble, ardupilot_msgs, MicroXRCEAgent, ArduPilot SITL, C++17

### Чему научился
- Работа с DDS в связке ArduPilot и ROS2.
- Проектирование конечного автомата для автономных миссий.
- Асинхронная работа с сервисами ROS2 с использованием конечного автомата в однопоточном режиме (Single Thread Executor).

### Сложности
- Подбор QoS: при несовпадении надёжности соединение не устанавливалось.
- Сервис "/ap/experimental/takeoff" сообщает о приёме запроса в работу, а не о выполнении — добавил ожидание завершения взлёта.
- Использование глобальной системы координат при управлении дроном - планирую маршрут в градусах, пересчитываю расстояние до целевой точки через гаверсинусы. В локальной системе было бы удобнее.

### Результат
- Дрон в SITL выполняет взлёт, облёт прямоугольника и посадку.
- Код: [controller_node_dds.cpp](src/drone_controller_cpp/src/controller_node_dds.cpp)

## - 2026-08-18

### ✨ Added
**Сборка первого пакета на C++**

Управление дроном через MAVROS на C++ с использованием конечного автомата (State Machine).

---

## 🚀 Возможности

- **Телеметрия**: подписка на топик `/mavros/state`, вывод состояния в реальном времени.
- **Управление**: последовательное выполнение команд:
  - Переключение в режим `GUIDED`
  - Армирование (`ARM`)
  - Взлёт (`TAKEOFF`)
- **Архитектура**: конечный автомат (`IDLE → WAIT_FOR_CONNECTION → SET_MODE → ARM → TAKEOFF → COMPLETE`).
- **Асинхронность**: все вызовы сервисов MAVROS выполняются асинхронно, без блокировки основного потока.
- **Тестирование**: работает в симуляторе ArduPilot SITL.

---

## 🧠 Архитектура

### Конечный автомат (`State Machine`)

```text
IDLE → WAIT_FOR_CONNECTION → SET_MODE → ARM → TAKEOFF → COMPLETE
                                ↓        ↓
                                ERROR    ERROR
```
**Каждый шаг:**

- Отправляет асинхронный запрос через MAVROS.
- В колбэке обрабатывает ответ и переключает состояние.
- Таймер (100 мс) управляет переходами, не блокируя поток.

## Компоненты

| Компонент | Назначение |
|-----------|------------|
| Подписка | Обновляет состояние MAVROS (`connected, armed, mode`). Колбэк короткий и неблокирующий. |
| Таймер | Запускает `control_loop()` каждые 100 мс. Управляет миссией по шагам. |
| Клиенты MAVROS | `set_mode`, `arming`, `takeoff` — асинхронные вызовы с колбэками. |

## 🛠 Стек

- **OS**: `Ubuntu 22.04 LTS`
- **ROS 2**: `Humble Hawksbill`
- **MAVROS**: `ros-humble-mavros`
- **Симулятор**: `ArduPilot SITL`
- **Язык**: `C++17`
- **Сборка**: `CMake + colcon`


## - 2026-07-31

### ✨ Added
**Сборка первого пакета на Python.** 

Реализован гибридный подход:
- **Телеметрия** получается через DDS-мост (MicroXRCEAgent + топики `/ap/...`).
- **Команды управления** (взлёт, движение) отправляются через DroneKit, подключённый к MAVProxy.

Такой подход позволяет использовать современный DDS для данных и надёжный MAVLink-канал для команд.
## 🛠️ Требования

- Ubuntu 22.04
- ROS2 Humble
- ArduPilot SITL (собран с поддержкой DDS)
- Python 3.10+
- Пакеты: `dronekit`, `pymavlink`, `microxrcedds_agent`

---

🧪 Пример использования

После запуска всех компонентов узел:

    Подписывается на топик /ap/pose/filtered (телеметрия).

    Выводит позицию дрона.

    Автоматически отправляет команду взлёта на 5 метров (через DroneKit).

При успешном запуске вы увидите сообщения о взлёте и рост высоты в телеметрии.

📌 Примечания

    Параметр DDS_ENABLE в ArduPilot может отсутствовать, это нормально — DDS-модуль активируется флагом --enable-DDS при запуске.

    Для изменения логики управления редактируйте controller_node.py.

    Для работы без DroneKit можно использовать MAVROS (экспериментально).
